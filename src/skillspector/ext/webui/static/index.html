2 Operations

Select repositories and operations.

Model tiles run the upstream LLM stage and the whole-skill judge. Explain and Sandbox use the model chosen next to Run (by default the first selected model tile). LLM tasks run one at a time; static tasks run in parallel. You can add repositories and start more runs while others are going: they join the waiting list.

3 Runs

API usage

Trust score uses repo age, star growth, forks, issues, owner type, license and contributors. It is a hint, not a verdict: always scan before installing.

Skill Library

Decide which skills to keep. A skill's colour is its worst verdict across every method you ran: safe, caution, do not install, not scanned. Deleted skills leave the library and the export. A repository is cleaned when every remaining skill is green. Manage scans (remove, redo, change method) on the Scan page.

Saved Skills

Only fully cleaned skills live here: every skill passed static rules, an LLM review, Explain and Sandbox with no yellow or red result. Saving moves a repository out of Scan and the Skill Library; this copy (with its review manifest and file hashes) is the one to install.

A pin records the commit and a hash of every file of a reviewed skill. Verify fetches it again and lists changed, added or removed files, so a skill that turns malicious after your review is caught. Re-scan anything that changed.
